v2.3.0
- Back in spacy's repository under the add-on id plugin.audio.amazonmedia. It takes over the versions 2.0.0 to 2.2.3 by Kai Sommerfeld (ksooo), listed below. You have to sign in once more.
- The requests follow the web player of Amazon Music as it is in November 2026: the configuration is loaded as the web player loads it, the API path takes its region from the music territory (/ZAZ/api/ for Europe), the access token is sent with every request and can be renewed via /pandaToken, and a manifest and a licence are asked for with the fields the player of the signed in web player sends.
- Playback of the web player was recorded with Chrome on Linux and a Prime account: it plays, and Chrome sends no Verified Media Path status there. The add-on asks for manifest and licence the same way, apart from the manifest version (V2 instead of the new FLAC/Opus manifests).
- New: When Amazon refuses the DRM licence because Kodi has no Widevine Verified Media Path (seen on Windows), the add-on does what the web player does: it remembers the refusal and asks for the next song as an unverified client. Whether Amazon then hands out a licence is up to Amazon; this has not been tried yet. The refused song has to be started again.
- New: Songs you own (purchases and uploads in the personal library) are asked for as the web player asks for them and come as a plain file without DRM, so they should play on every platform. Not tried in Kodi yet.
- Fixed: The add-on could not be installed where script.module.mechanicalsoup was missing. The sign-in no longer needs it; it works with requests and BeautifulSoup alone.
- Fixed: When Amazon asks for a code it has sent by SMS, the add-on showed a waiting dialog that could only be cancelled. It now shows what the page says with OK (enter the code), "Resend code" and "Verify with WhatsApp"; the dialog's Cancel ends the sign-in. If a message to the smartphone is offered as well, the page is not polled any more. The text of every verification page is written to the log.
- Fixed: A playlist of your own failed to open when Amazon handed one of its songs over without details.
- New: When Amazon refuses a DRM licence, a notification names the reason. An untrusted Widevine library (UNTRUSTED_DEVICE_CERTIFICATE, seen with a library of April 2024) asks you to update it with InputStream Helper.
- New: Before a protected song plays, InputStream Helper checks InputStream Adaptive and the Widevine library and offers to install or update them. A fresh Kodi on a desktop has no Widevine library; the song then did not start at all.
- Kodi 21 no longer gets two stream properties it warns about.
- Fixed: Kodi on a Linux desktop named itself as Chrome for Windows. Amazon then expected a Verified Media Path, which Chrome has on Windows and not on Linux, and refused every licence (VMP_VALIDATION_FAILED, seen with Kodi 21.3 and a current Widevine library). It now names itself as Chrome for Linux, whose Widevine library it uses.
- Fixed: On Linux, Windows and macOS songs of the catalogue stopped after their unprotected start. Amazon licenses none of the qualities of the manifests the add-on asked for to a player without a Widevine Verified Media Path, which Kodi has on Android alone (VMP_VALIDATION_FAILED for the best and for the lowest quality). There the add-on now asks for the manifest the web player asks for and plays the one quality Amazon licenses to such a player, as the web player does on a Linux desktop. That quality is low. Songs you own are not affected.
- Fixed: On Windows a list of albums failed to open when it held an album released before 1970 (OSError: Invalid argument).
- Kodi on Windows: Amazon refuses the licence for songs of its catalogue in every quality, because it expects a Widevine Verified Media Path there. After such a refusal the add-on says so and no longer plays the unprotected start of song after song; it asks Amazon again a day later. Songs you own play.
- The sign-in is kept as plain data (data.json) instead of a pickled Python object, which runs code when it is read. A sign-in of an earlier version is taken over by its cookies; the old file is not read any more and is removed.
- The add-on names itself as the current Chrome (157).
- Inside: one small function per request and per kind of list instead of two long chains of conditions; the requests themselves are unchanged.
- Every request to Amazon has a time limit now (10 seconds to connect, 30 for an answer); without one, a request that got no answer blocked the list or the song for good.
- New: Search, artists, albums, playlists, your own and followed playlists, and the songs, albums and artists of the library are asked for through the GraphQL interface of the current web player (gql.music.amazon.<tld>). The older interfaces for these lists (muse artist details, textsearch, the playlists service and the cirrus library of artists, songs and album tracks) are removed; should a query fail, the add-on says so and writes why into the log. The recommendations (the playlists and albums on the shelves of the start page), the popular and new playlists and albums, the pages of a search and the followed playlists (all of them, not 15) come from GraphQL as well. Only bought albums and recently added songs still come from the older interfaces, as GraphQL has no list of them. A search shows 30 results per page with a next page; Amazon has no charts of songs or new songs for the account tried, so these two menus are gone.
- New: Genres (with moods and activities) and radio stations in the main menu, with the images genres.jpg and stations.jpg. A genre lists its shelves of playlists and albums; a station plays ten songs at a time, and its next page starts a new queue with other songs.
- The search and its history show search.png.
- The licence request goes through the local proxy of the add-on, which logs why a licence was refused.
- A refused access token no longer fails a request as long as the sign-in cookies are good.

v2.2.3
- Fixed: Some days after signing in, almost every list failed with an error. The tokens Amazon hands out at sign-in expire, while the sign-in itself lasts longer. They are renewed now when Amazon refuses them, without signing in again.

v2.2.2
- Fixed: Followed and own playlists failed to open with an error since 2.2.1. The playlists service hands over the banner with its size, which Kodi did not take as fanart. Now it is their fanart.

v2.2.1
- Fixed: Covers were set as fanart, poster, banner and landscape, where their square shape does not fit. They are icon and thumbnail only now. Playlists with a wide banner show it as fanart.
- Fixed: Menu entries also set their images as poster, banner and landscape, where their shape does not fit.
- Fixed: Artists without an album of their own opened an empty folder. They list their songs on the albums of others instead.

v2.2.0
- New: A search history per kind of search replaces the last three searches. It keeps up to 25 terms, the latest first. An entry searches again, and "Remove Search" in its context menu removes it. The last three searches of older versions are taken over.
- New: Search and search history show the icons of MediathekView+, and menu entries show their icon in list views such as WideList.
- Fixed: Songs added to the personal library from the catalogue counted as unplayable and were hidden in Personal Library and among the songs of a library artist.
- Fixed: Followed and own playlists ended after the first 100.
- Fixed: The genre of a playing song reached Kodi as "['Pop']" instead of "Pop".
- Kodi 22: The license request uses the new inputstream.adaptive property, so its deprecation warning is gone from the log.

v2.1.0
- New: Albums and songs have lists of newly released and popular titles, as playlists already had.
- New: Artists have the personal library. An artist opens its songs in the library.
- New: An empty list of songs recently added to the personal library says that nothing was added in the last 90 days.
- The menus list their entries in the same order.
- Removed: The recommendations in the main menu. Amazon only filled them with a single list, titled in English whatever the language, and most of its playlists are under Playlists / Popular. Playlists and Albums keep their recommendations.
- Removed: The setting "Show colored entries". Entries are always marked: gold for purchases, red for titles that cannot be played.
- Fixed: Playlists and albums Amazon does not stream to the account were listed in red, but could not be opened. They are left out now.
- The domain setting is called "Sign-in domain", and its help says it has to be the Amazon site the account is registered with.
- "Owned" is called "Personal Library", and "Recently Added" says that it is about the personal library. German spells "Addon".

v2.0.0
- Independent continuation of spacy's add-on, which is no longer developed. It has its own add-on id now, so you have to sign in once more.
- Signing in works again. Amazon had changed its sign-in pages and its web player.
- Playback works again.
- Important: Playback needs Kodi for Android. On desktop Amazon refuses to hand out the DRM licence.
- Removed: Stations, genres and the recently played songs. Amazon has withdrawn the services behind them.
- New: The path to the folder you are in is shown top left, after the add-on name. Menu entries no longer repeat the name of their menu.
- Fixed: Kodi could hang when you quit it after having played something.
- Fixed: Search did not return any results.
- Fixed: A failed request signed you out instead of just reporting the error.
- Fixed: Signing in did not continue after the notification was approved on another device.
- Fixed: The approval prompt did not say where the notification had been sent.
- Fixed: Artist and playlist listings came back empty.
- Fixed: With a Prime account nearly everything counted as unplayable and was left out of the listings.
- Fixed: Your own library and the recently added songs failed with an error. Amazon had withdrawn the endpoint they used.
- A title Amazon does not release for streaming, such as a purchase outside its catalogue, now says so instead of reporting a missing streaming URL.
- Fixed: German notifications were partly English, had a colon after the title and a wide gap, and showed errors as information.
- Translations revised: German uses the infinitive, "Wiedergabelisten" and "Titel", French and Italian are complete now and corrected.
- Settings revised: unplayable songs are hidden by default, the setting for showing all images is gone, and every setting explains itself in a help text.
